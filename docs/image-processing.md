# 업로드 이미지 처리 정책

옷 저장, 채팅 첨부, 의류 분석의 신규 업로드는 `ImageProcessor`를 거친다.

1. 기존 20MB 용량 제한, JPEG/PNG 시그니처 검사, 가로·세로 8,192px 및 총 2,000만 픽셀 제한을 적용한다. 픽셀 제한은 전체 디코딩 전에 검사한다.
2. 한 번 디코딩한 이미지에서 EXIF Orientation 1~8의 회전·반전을 보정한다. 방향 값이 없으면 원래 방향을 사용하며, 잘못된 방향 값은 입력 오류로 거부한다.
3. 긴 변이 최대 2,048px이 되도록 종횡비를 유지해 축소한다. 작은 이미지는 확대하지 않는다. 정수 픽셀 반올림에 따른 최대 1px 차이는 허용한다.
4. 원본 메타데이터를 복사하지 않고 새 래스터를 인코딩한다. JPEG는 품질 0.85, PNG는 무손실 인코딩과 알파 채널을 유지한다. EXIF/GPS, 원본 썸네일, 원본 텍스트 메타데이터는 전달하지 않는다.

`ProcessedImage`의 바이트와 MIME 타입을 S3 업로드 및 AI 전송에 사용한다. S3 확장자와 Content-Length도 처리 결과를 따른다. 채팅에서는 동일한 처리 결과를 두 경로에서 공유한다.

비동기 분석은 접수 시 처리된 바이트와 MIME 타입을 DB에 저장한다. 작업 실행 시 사용하는 `analyze(byte[], MimeType)`는 이 내부 저장 결과를 받는 경로이며, JPEG 재압축을 피하기 위해 다시 인코딩하지 않는다. 원본 업로드를 이 메서드에 직접 전달하지 않는다.

## 배포 범위

기존 S3 객체와 기존 분석 작업의 이미지 데이터를 일괄 변환하지 않는다. 배포 전에 생성된 미완료 분석 작업에는 원본 데이터가 남아 있을 수 있으므로, 신규 정책을 모든 실행 작업에 적용하려면 기존 작업을 먼저 소진하거나 별도 데이터 전환이 필요하다.

## 검증

실제 JPEG/PNG에 삽입한 EXIF/GPS로 방향·메타데이터 제거를 확인한다. JPEG 8방향의 색상 위치, 리사이즈, 작은 이미지 크기, PNG 투명도, S3·AI 전달 데이터, 처리 실패 시 후속 작업 차단을 테스트한다. 실제 S3/OpenAI 연결 없이 요청 데이터를 캡처한다.
